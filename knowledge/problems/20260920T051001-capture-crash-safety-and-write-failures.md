title: Recordings lost their manifest on restart and died silently on write failure
---
- **Symptom:** Two separate ways to lose a recorded session with no evidence. (1) Any restart during a recording — crash, `--reload`, Ctrl-C, sidecar respawn — discarded the open 10s/1m/5m/1d buckets and left `manifest.json` holding only the `start_recorder` shape, so the Sim replay picker reported `prints: -1` ("present but unknown") for that session forever; a later Record on the same symbol+day then reset counts to zero while the jsonl kept appending, so the manifest understated the file (8 rows on disk, `counts.prints: 3`). (2) A disk-full or unplugged-drive write raised `OSError` out of `record_print`, the only catch on the path logged at `DEBUG` while root is `INFO`, so ENOSPC produced **no log line, no API field, no UI change** — `/api/capture` kept answering `recording: true` while nothing was written, and the raised exception also aborted quotes, L2 and bars for that tick.
- **Cause:** The recorder kept its whole session in process globals with nothing persisted, and `app_lifespan`'s shutdown block flushed HOD alerts, L2, the scan executor, the sim feed, IBKR and logging — but never the capture recorder. `start_recorder` built a fresh manifest dict and `write_text`-ed it unconditionally, zeroing `_counts` while opening the jsonl files in `"a"` mode; the `resume: bool = True` parameter it accepted was never read. Nothing in `backend/capture/` used `fsync` or `os.replace`, so `manifest.json` was truncate-then-write and could be found half-written. And `_write` had no `try`/`except` at all around `fh.write` / `fh.flush`.
- **Fix:** Four changes. `app_lifespan` now calls `capture.mode.set_capture_mode(False)` on shutdown (next to `l2.batch.flush()`) and finalizes an orphan on startup. A marker file (`capture/session_state.py`) names the in-flight session, so a hard kill is detected on the next boot and the session is recounted from disk and stamped `status: "interrupted"`. `capture/manifest_io.py` writes the manifest atomically (temp + `fsync` + `os.replace`, the `backend/archive/manifest.py` pattern) and **merges** rather than clobbers — first `started_et` preserved, a `segments[]` entry per run, cumulative `counts` seeded from the prior manifest so they always match the rows on disk; `resume=False` is now honoured (truncate + fresh manifest) instead of ignored. `_write` catches `OSError`/`ValueError`, logs at ERROR with the traceback, counts consecutive failures, fsyncs every ~5s, records `last_write_ts`, and after `CAPTURE_MAX_WRITE_FAILURES` finalizes the session as `failed`; `capture.mode.status_payload()` now follows the recorder instead of its own flag, so `/api/capture` goes red **with the error**. `sim/feed.py`'s capture-bridge catch was raised `debug` → `warning`, and `sim/capture_player.py` now reports a torn jsonl tail instead of dropping it silently.
- **Keywords:** capture recorder crash safety, manifest.json atomic os.replace fsync, resume overwrites counts, prints -1 unknown, ENOSPC silent, disk full recording lost, interrupted session recovery, last_write_ts, D-067, D-068, #318, #319
