1. Intent (what this system must do)

Primary function: Emit Warrior-style alert-scanner rows for Small-Cap High-of-Day Momentum when a symbol prints a new session high and also passes a configured momentum / float / RVOL sub-strategy.

Sibling function: Emit Running Up alerts (strategy #12) for quick % moves that do not require a new HOD. Same engine; separate UI tab.

Non-goals: Do not stream Level-1 for the entire US tape. Do not invent session highs from the first last print. Do not silently fall back to Alpaca prices. Do not place orders from this path.

Core product rule (Warrior KB / BA101): HOD Momentum ≠ “every print at the high.” It is new high-of-day + above-average momentum matching a sub-strategy. Mere retests of an already-set high belong to Running Up (or no alert).

2. End-to-end pipeline (raw data → UI row)

0
Discovery universe (watch set)
Focus mode unions Top Gainers / Gappers / AH movers with IBKR volume scanners (HOT_BY_VOLUME, TOP_VOLUME_RATE, MOST_ACTIVE) — retired. As of ADR 008 (2026-07-23) the HOD watch set is exactly the current-session retained Gappers ∪ Gainers ∪ Afterhours ∪ manually curated Former Momo — no separate seed scans.
1
Active set (capacity 40)
Only 40 symbols get persistent IBKR reqMktData L1 for HOD evaluation. Admission order: manual Former Momo first (every registered symbol guaranteed a slot — an oversized list is rejected outright rather than silently truncated), then deterministic round-robin across ranked Gappers / Gainers / Afterhours queues. No volume-seed, explore, open- ticker, or Losers quota. Everyone else is uncovered (watched, not live).
2
Raw trade / quote input
IBKR L1 last + cumulative volume (+ tick type 6 day high when present) → hod_momo_trade.on_trade_update(symbol, price, ts, volume, day_high).
3
Session state update
Update rolling price buffer · queue surge historical seed · apply day-high seed · raise observed high · refresh snap (price, volume, paced RVOL, 5m RVOL).
4
Gate ladder (see §5) — blocklist → master → per-strategy HOD → strategy filters → integrity suppress.
5
Consolidation queue
Passed alerts wait up to consolidation_sec (default 10s) so Warrior-style “(N in Xs)” can batch.
6
Persist + broadcast
Alert object → in-memory day list → rate-limited disk snapshot → WebSocket to UI → frontend partitions strategy #12 into Running Up tab; rest into HOD Momo tab.

3. Capacity model — why 8,000 ≠ 100

Hard constraint: IBKR market-data pacing and Nova’s L1 owner model cannot stream thousands of symbols with a ≤2s quote/eval SLO. The design deliberately separates discovery (large, cold) from evaluation (≤40, hot).
LayerTypical sizeWhat it doesSLA
Discovery / watch universe ~50–200 Current-session Gappers ∪ Gainers ∪ Afterhours ∪ Former Momo (ADR 008; no volume seeds) Pushed by persistent scanner subscriptions; frozen tables stop contributing new members
Active evaluation set 40 max Persistent L1 → trade updates → strategy eval Quote/eval p95 ≤ 2s, max ≤ 3s
Uncovered watch − 40 Known to integrity banner; not a bug list to chase May rotate in via explore / movers / seeds
Surge seed queue pending ≤ few Historical 1-min bars (15) to warm Squeeze windows Max 2 symbols/tick — IBKR historical pacing
Fundamentals active batch 10 Float / avg volume / 52wk from yfinance Cache TTL 900s; active refresh every 300s

If we tried to process 8,000 like 100

  • Qualify + subscribe storms → API hang / CLOSE_WAIT / integrity timeouts (already observed historically).
  • Quote ages climb to minutes → false “Integrity fail” and missed squeezes.
  • Correct scaling path: keep active=40, improve who gets the 40 slots (priority), not “stream everyone.”

Why it can feel like “going backward”: Config on disk can drift from code defaults (user toggles, old schema). Schema migrations repair known bad states (e.g. Squeeze with requires_hod=False). Integrity suppress can mute correctly-passed strategies when a scanner bridge error flips merged integrity to fail — alerts look “broken” while L1 is green.

5. Every gate — English SSRD statements

Order matches on_trade_update. A gate that fails stops that path for the symbol (or that strategy). Tags: Hard = blocks emit · Soft = warn-only integrity · Cap = capacity · Post = after strategy pass.

G0 Engine armed

  • Requirement: At least one strategy config must be loaded.
  • Fail: No configs → function returns; no evaluation.
  • Store: In-memory state.configs from disk defaults/migrate.

G1 Admission to live tape (active set)

  • Requirement: Symbol must hold one of ≤40 active L1 slots to receive continuous trade updates for eval.
  • Pass inputs: Priority reasons — open ticker, session focus, top gainer/gapper, volume seed, explore rotation.
  • Fail / uncovered: Symbol may exist in discovery but never call on_trade_update → cannot fire.
  • Note: This is the main answer to “why didn’t X appear?” when X was never active.

G2 Blocklist

  • Requirement: Symbol must not be on the HOD blocklist.
  • Fail reason: blocklist
  • Store: hod-momo-blocklist.json

G3 Master gate (data readiness + optional master surge)

  • Requirement: Price must be known and > 0.
  • Optional: If master surge % / window > 0, rolling buffer must show that surge (usually disabled — master RVOL retired).
  • Fail examples: master_data:no_price, master_surge:…
  • Note: Master gate does not own HOD anymore; HOD is per-strategy (G5).

G4 Strategy enabled + Former Momo membership

  • Requirement: Strategy enabled=true.
  • Former (#1): Symbol must be on the Former list (else blocked). Former defaults off.
  • Fail: disabled, Former membership reasons.
  • Controller: UI strategy toggles → persisted config.

G5 HOD gate (requires_hod + new-high grace)

  • Applies when: strategy requires_hod=true AND master hod_required=true.
  • Running Up (#12): requires_hod=false → this gate is skipped.
  • Pass criteria (all):
    1. Session high is seeded (from bars / tick-6 day high — never invented from first last).
    2. Last price is at/near session high (ε = max($0.01, 0.1% of high)).
    3. Session high was raised recently — within HOD_MOMO_NEW_HOD_GRACE_SEC = 60 seconds.
  • Fail examples: hod:high_unseeded, hod(price<hod), hod:not_new, hod:stale_new(…)
  • Who sets requires_hod: code defaults · UI checkbox · disk config · schema v5 forces Squeeze #10/#11 back to true.

Checked in order. Any 0-threshold means “disabled / ignore.”

Raw mode env HOD_RAW_MODE skips G6 (not for production parity).

G7 Integrity suppress (post-pass mute)

  • Requirement to emit: Merged integrity status must not be fail when HOD_MOMO_SUPPRESS_ALERTS_ON_INTEGRITY_FAIL=true.
  • Fail token: integrity_fail_suppress
  • Critical nuance: Runs after G5+G6 already passed. Strategy “passed” in logs, then muted.
  • Known defect (2026-07-23): Sticky scanner_ibkr_bridge TimeoutError can fail merged integrity while HOD L1 is green → false mute (RBNE Squeeze case).

G8 Consolidation / emit

  • Requirement: Alert sits in per-symbol consolidation bucket for up to 10s, then emits (Warrior burst badge semantics).
  • Per-strategy cooldown currently default 0 (off).

G9 Integrity banner checks (observability, not strategy filters)

These do not replace G0–G8; they explain the red/yellow banner and can feed G7.

  • hod_ticks_flowing — trades arriving
  • hod_active_set / quote / eval ages — active SLO
  • hod_surge_after_seed — seeded but still surge=None (usually warn)
  • scanner_ibkr_bridge — discovery bridge error sticky (can hard-fail merge)
  • Uncovered list — capacity design, not a miss scoreboard

Supporting data gates (feed quality)

High seeding
  • Bars / IBKR tick-6 establish floor → high_seeded=true
  • Later print above floor stamps session_high_raised_ts
  • Without seed, all requires_hod strategies hard-block
Surge seeding
  • Historical 15× 1-min bars warm the price buffer
  • Without it, Squeeze can see surge=None mid-move
  • Queue paced at 2 symbols/tick
RVOL / fundamentals
  • Paced RVOL = cum vol vs avg daily volume
  • Fundamentals TTL 900s; active refresh 300s
  • Float-unknown blocks float-gated strategies
Expiration / day boundary
  • Session reset 4:00 AM ET
  • Clears highs, buffers, day snaps (process policy)
  • Alerts file is dated; “Clear today” wipes shared store

7. Running Up vs HOD (sibling scanner)

HOD Momo tab

  • Strategies 1–11
  • Warrior: Small Cap HOD Momentum
  • Needs new HOD (for Squeeze / floats)

Running Up tab

  • Strategy #12 only
  • requires_hod=false
  • Defaults: surge ≥5% / 5 min · min_rvol ≥2
  • Can fire earlier / on pullback squeezes
Same tick, both pass is legal: new HOD + 5%/5min + rvol≥2 → #11 and #12 both qualify. UI must still split them. If both show integrity_fail_suppress, neither row appears — that is mute, not “wrong tab.”

8. How to prove it works (acceptance checks)

  1. Feed alive: GET /api/integrity → parts.hod_momo is pass/warn; active quote p95 ≤ 2s; IBKR connected.
  2. Admission: For a Warrior alert symbol, /api/hod-momo/debug/symbol/SYM shows it active (or explain uncovered).
  3. Gate trail: backend/logs/hod_momo.log at Warrior timestamp shows gate=passed or exact blocked_by.
  4. True fire: counter strategy_11_fired increments and alert appears on HOD tab (not only “passed then suppress”).
  5. Negative proof: retest of old high without raise → hod:not_new / hod:stale_new for Squeeze; Running Up may still pass.
  6. Parity sample: pick N Warrior Squeeze rows in a window; classify each Nova miss as universe / L1 / HOD / surge / filter / integrity mute.
RBNE worked example (2026-07-23 11:58:26 ET): Active as top_gainer · price $5.90 · HOD + Squeeze + Running Up filters passed · both muted by integrity_fail_suppress (sticky scanner bridge TimeoutError). Classification: infra false mute, not missing Squeeze rules.
